# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A reusable LaTeX template + Makefile build system for writing papers for top AI/ML conferences and
journals (AAAI, IJCAI, ECAI, JAIR, NeurIPS, ICML, ICLR, ACL/ARR family, CVPR, JSAI) and for producing
their submission-specific artifacts (anonymized submission, camera-ready, Arxiv archive). There is no
application code, no test suite, and no linter — "correctness" means "the PDF builds and follows the
target venue's formatting/submission rules."

Requires: GNU Make, TeX Live, Inkscape, Perl, GNU awk (`gawk`, not BSD awk). Developed/tested on Fedora
Linux; partially works on OSX (some `find`/BSD-awk incompatibilities exist).

## Common commands

- `make` — build `<name>.pdf` (default `<name>` is `default`) and `standalone-supplement.pdf`, using
  `latexmk` via `latexmk/latexmk.pl` with `-shell-escape -halt-on-error -bibtex`.
- `make auto` — watch sources with `inotifywait` and rebuild on change (Linux only); desktop
  notifications via `scripts/make-notify-and-wait.sh` / `scripts/make-periodically.sh`.
- `make submission` — build a `<name>.submission/` directory containing a single flattened `.tex` file
  (all `\input` inlined, `.bbl` inlined) with images renamed/relocated to the top level, per AAAI/IJCAI-
  style camera-ready rules. Driven by `scripts/submission.mk`.
- `make archive` — same as `submission`, then produces `<name>.zip` and `<name>.tar.gz` with `.sty`/`.bst`
  files stripped (required by some venues; AAAI does not accept `.tar.gz`).
- `make arxiv` — same as `archive` but keeps the style files (needed since Arxiv recompiles from source).
- `make clean` / `make allclean` — remove build byproducts (and, for `allclean`, also `img/`'s compiled
  figures).
- Rebuttals: `cd rebuttal && make` builds `journal-rebuttal.pdf` (uses `\begin{review}/\end{review}` and
  `\begin{reply}/\end{reply}` environments with cross-references). `rebuttal.org` is an Emacs org-mode
  file that auto-exports to plaintext on save, for submission systems (e.g. EasyChair) that only accept
  plaintext rebuttals.

There is a `name` variable at the top of `Makefile` (default `default`) — AAAI requires the submitted
`.tex` file to have a specific name (e.g. `PLT-AsaiM.37`); change `name` there rather than renaming files
by hand. `$(name).tex` is autogenerated (just `\input{main.tex}`) and auto-added to `.gitignore`.

## Architecture: the `\input` chain

The build is a chain of `\input`s (not `\usepackage`, deliberately — see below) rooted at `<name>.tex`:

```
<name>.tex (autogenerated)
  -> main.tex                        toplevel: preamble hookup, \maketitle, per-venue author/title blocks (commented alternatives for AAAI/ICML/ECAI/JAIR live inline — uncomment the one you need)
       -> styles/header.sty          shared preamble
            -> styles/patches.sty        fixes for ill-behaved conference .sty files (package option clashes, \AddToHook ordering)
            -> styles/confs/<venue>.sty   exactly one of these is uncommented at a time; each wraps the official venue style
                 -> styles/official/*.sty     vendor-provided, unmodified style/class/bst files
            -> styles/math.sty, styles/general.sty, styles/abbrev.sty   custom macros (see below)
            -> parts/strips.sty, parts/heuristics.sty   paper-specific macro packages
       -> body.tex                   main paper content (\begin{document}..\appendix) — where most editing happens
       -> supplemental.tex           appendix content (\appendix..\end{document})
standalone-supplement.tex            separate toplevel for venues (AAAI, IJCAI) requiring a standalone supplement PDF with its own title page; cross-references main.tex/supplemental.tex via the `xr` package
```

Switching target venue = editing `styles/header.sty` to uncomment the desired `styles/confs/*.sty` line
(and only that one), then adjusting the author/title block in `main.tex` to match that venue's convention
(examples for several venues are present but commented out).

`\input` (not `\usepackage`) is used throughout for anything paper-specific so that `make submission`'s
inliner (`scripts/inline.sh` + the `inline-*.awk` scripts) can flatten everything into one `.tex` file,
as several venues require. Consequence: **every `\input{...}` must be alone at the start of its line**
(`scripts/inline-check.sh` enforces this) — text before/after an `\input` on the same line will be
dropped by the inliner.

`styles/general.sty` defines a `dev` toggle driven by the `--shell-escape` state (see there): it gates
`\todo{}` (visible only in dev builds) and the `minted`/pygments cache mode (`finalizecache` while
developing, `frozencache` for submission builds that lack `--shell-escape`, e.g. Arxiv). It also
redefines `\ref` to force use of the semantic `\refsec`/`\refig`/`\reftbl`/... macros instead, for
consistent "Fig./Sec./Table" styling; the camera-ready script strips this redefinition automatically.

## Figures

Put vector sources as `.svg` under `img/` (compiled to `.pdf` via Inkscape by `img/Makefile`); put
non-vector/pre-rendered assets under `img/static/`. Vector→PDF is preferred over bitmap for print quality
and file size. `git-add-all-used-images.sh` finds images actually `\includegraphics`'d in the tracked
`.tex` sources and `git add`s just those (useful since `img/` may accumulate unused figures).

## Submodules

`.gitmodules` declares `org-mode` and `authorkits/acl-style-files` — run `git submodule update --init`
if either is needed and missing.
